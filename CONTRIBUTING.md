# Contributing to JukaMix OS

Thanks for wanting to help! JukaMix is an independently maintained derivative of
CrossMix-OS for the TrimUI Smart Pro, TrimUI Smart Pro S, and TrimUI Brick. This
guide covers what's welcome and the rules that keep the tree healthy.

## What's welcome

| Contribution | Where | Notes |
|---|---|---|
| Game collections | `Best/<PackName>/` | See the format spec below |
| Themes | `Themes/` | Drop-in — full UI themes |
| Icon packs | `Icons/` | Drop-in |
| Wallpapers | `Backgrounds/` | Per-system, drop-in |
| Emulator configs / launcher fixes | `Emus/<platform>/` | Must stay POSIX sh (see below) |
| On-device tooling | `System/usr/trimui/scripts/`, `bin/`, `tools/` | POSIX sh, no bashisms |
| Build / validation tooling | `scripts/`, `tests/` | Host-side; never ships in the image |

## Best pack format spec

A collection pack is a folder under `Best/`:

```
Best/FreeGamesCollection/
├── config.json     # required
├── icon.png        # required
├── bg.png          # optional background
├── launch.sh       # optional custom launcher
├── Imgs/           # per-game artwork
└── Roms/           # the games
```

`config.json` fields:

```json
{
  "label": "Free Games Collection",
  "icon": "icon.png",
  "background": "bg.png",
  "themecolor": "f0b402",
  "launch": "launch.sh",
  "rompath": "./Roms",
  "imgpath": "./Imgs",
  "useswap": 0,
  "shortname": 0,
  "hidebios": 1,
  "extlist": "gba|nes|n64|z64|smc|7z|zip|gb|md|iso|cue|sfc|nds|bin|img|chd|elf|txt|launch"
}
```

- **The folder name must not contain spaces** — the on-device name comes from
  `config.json` `label`, not the folder name. A space in the path splits into
  two words in every unquoted shell expansion that touches it.
- Only ship games that are freely redistributable (homebrew, public-domain
  ports, freeware). No commercial ROMs in the repo.

## Shell code rules (important — the device shell is busybox ash)

All on-device scripts run under **busybox ash** (OpenWrt-based TrimUI
firmware). Worse, the first-boot firmware check symlinks `/bin/bash` to busybox,
so **no script gets a real bash** — not even ones with `#!/bin/bash`. Anything
bash-only crashes at runtime. This is enforced by CI via
`scripts/validate.sh`:

- No `[[ ]]` — use `[ ]` or `case`
- No `source` — use the POSIX dot `.`
- No `${var//pattern/repl}` or `${var:offset}` — use `sed`/`tr`/`case`
- No `let` — use `$((x + 1))`
- No `&>` — use `> file 2>&1`
- No herestrings `<<<`
- No `local`-in-`/bin/sh` concerns beyond what busybox ash supports
- **Quote every expansion**: `"$var"`, `"$@"`, `"$(cmd)"` — the on-device
  paths (`/mnt/SDCARD/...`) and the `Best/` folder names must never be
  unquoted.

## What never belongs in a PR

- **User data**: `Roms/`, `BIOS/`, `Saves/`, `States/`, `Pictures/screenshots/`
  track only `.gitkeep` scaffolding and OS-provided content (bezels, machine
  definitions). The updater promises to never touch these paths — a PR that
  adds real files there breaks that promise.
- **Firmware blobs**: `trimui/firmwares/` is fetched on demand by
  `scripts/fetch_firmware.sh`. Multi-hundred-MB `.7z.001` parts stay out of git
  and out of history.
- **Build artifacts**: `SHA256SUMS`, `MANIFEST.json` and the release zip are
  generated by `scripts/build_release.sh` into `dist/` (gitignored).

## Before you open a PR

1. Run the validator:

   ```sh
   sh scripts/validate.sh
   ```

2. If you touched device coverage, run the device gate:

   ```sh
   sh scripts/validate_devices.sh . --devices "tsp tg5050 brick"
   ```

3. If you touched shell code, confirm the POSIX scan passes and the changed
   files parse under strict POSIX:

   ```sh
   bash --posix -n <changed-file>
   ```

4. Keep PRs small and focused; one logical change per PR. Explain *why* in the
   description.
